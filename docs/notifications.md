# 通知内容与验证范围

所有通道继续使用纯文本。Telegram 不设置 parse_mode/entities；长内容分段并标注段号，逐段检查业务 ok 值，失败停止，不自动重发已发送的段。

## 通知清单

| 类别 | 内容与定位 |
| --- | --- |
| 连续模型失败 | 五次上游尝试、时间范围、最近错误、按来源分组的供应商/模型/Key名称与ID/UA/IP/请求ID |
| 路由备用组 | 路由、分组、供应商、模型、成功结果、客户端来源与请求ID |
| 路由不可用/不兼容 | 路由、协议或HTTP结果、原因、客户端来源与请求ID |
| 供应商额度耗尽 | 供应商、后台查询来源、影响与上游重置时间 |
| 套餐额度预警 | 每家供应商、窗口、比例、阈值与绝对重置时间 |
| 日报/周报 | 统计日期与时区、请求/成功/失败/Token/花费；常用与失败模型标明供应商 |
| 花费异常 | 统计日期、今日花费、前7日均值、倍数与阈值、未计价样本 |
| 全局失败率 | 时间起止、比例与阈值、错误/未知构成、前三供应商与模型 |
| Key预算/到期 | Key名称和ID、滚动窗口/额度/比例或完整到期时间 |
| 上游模型变动 | 供应商、模型、下架或价格变化 |
| 免费模型维护 | 供应商、路由、逐项新增/启用/停用/策略变化 |
| 定时任务失败 | 任务名称与ID，后台任务记录定位；不外发原始错误 |
| 连接测试 | 明确为管理员手动测试，不冒充故障 |

## 语义与隐私

- 连续失败沿用模型级五次上游尝试阈值，成功清零，客户端取消不计数；不是五位用户或五个独立会话。
- 调用身份来自网关Key的可读名称与数据库ID，不包含真实Key；它不能证明具体个人身份。
- UA是客户端声明值；IP沿用网关现有可信反代识别规则。未知字段显示未记录，未凭空推断客户端。
- 不收集或发送请求正文、原始上游错误或凭证；动态字段去除控制字符与换行并限制长度。
- 发送时间使用完整UTC标记，定时通知的到期与窗口时间保留配置时区并标明偏移；金额统计不是供应商账单。
- 实时与定时通知原有阈值、冷却和去重策略保持。

## 验证

使用本地HTTP桩覆盖混合来源、成功清零、长Unicode纯文本分段、Telegram业务失败与任务错误脱敏；不向真实Telegram会话发送测试消息，不启动浏览器。
